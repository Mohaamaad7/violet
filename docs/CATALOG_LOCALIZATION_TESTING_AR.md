# تجربة تحديث ترجمة المنتجات والأقسام على test

## ما الذي تغيّر؟

- لكل منتج وقسم حقلا اسم مستقلان: `name_ar` و`name_en`، مع حقول مستقلة للوصف ومحتوى المنتج وSEO.
- حقول العربية والإنجليزية في تبويبين داخل Filament. الاسم الأصلي محفوظ للرجوع إليه ولا يتغير رابط السجل أو SKU أو علاقاته.
- المنتجات الجديدة تبدأ كمسودة. الاسمان مطلوبان عند اختيار الحالة «نشط». الأقسام النشطة تحتاج الاسمين أيضاً، والنشر الجماعي يرفض المجموعة كاملة إذا كان أحد المنتجات ناقص الترجمة.
- لا يُعرض اسم باللغة الأخرى عند نقص الترجمة. يظهر «قيد الترجمة #ID» / `Awaiting translation #ID` حتى اكتمال الاسم المطلوب. الأوصاف غير المترجمة لا تستعير وصف اللغة الأخرى.
- البيانات القديمة لم تُترجم آلياً: فُصلت الأسماء الواضحة مثل `العناية بالبشرة (Skin Care)`، ونُقل النص أحادي اللغة إلى حقله المناسب فقط. النص المختلط غير الواضح محفوظ للمراجعة ولا يُفصل بتخمين.

## تجربة مدخل البيانات

1. افتح `https://test.flowerviolet.com/admin/products` وسجّل الدخول بحساب لديه صلاحية تعديل المنتجات.
2. استخدم فلتر «أسماء تحتاج ترجمة» لاختيار منتج قديم، أو أنشئ منتجاً تجريبياً كمسودة.
3. في تبويب العربية أدخل مثلاً «غسول تجريبي» ووصفاً عربياً. وفي English أدخل `Test Cleanser` ووصفاً إنجليزياً. لا تكتب اللغتين داخل الحقل نفسه.
4. احفظ كمسودة مع اسم واحد: يجب أن يُسمح بذلك. حاول جعل الحالة «نشط» مع اسم ناقص: يجب أن يظهر خطأ للحقل المطلوب. أكمل الاسمين ثم احفظ كمنتج نشط.
5. افتح صفحة المنتج على واجهة المتجر. بدّل اللغة من زر الهيدر؛ يجب أن يتغير اسم المنتج والوصف والقسم واسم الصورة وSEO إلى اللغة المختارة فقط، مع بقاء الرابط والسعر والمخزون كما هي.
6. ابحث عن «غسول تجريبي» ثم `Test Cleanser`. البحث يتعرف على الترجمتين، ويعرض نتيجة البحث باسم لغة الواجهة الحالية.
7. عدّل اسماً واحفظه، ثم أعد فتح الواجهة باللغتين. يجب أن يظهر التعديل فوراً بعد الحفظ؛ يتم مسح كاش صفحات المتجر تلقائياً.

## تجربة الأقسام والهيدر

1. افتح `https://test.flowerviolet.com/admin/storefront-settings` وتأكد أن القالب المختار `category_first` (الأقسام أولاً).
2. افتح `https://test.flowerviolet.com/admin/categories`. راجع الأقسام الرئيسية الموجودة، وتأكد من تفعيل «إظهار في هيدر قالب الأقسام أولاً» و«إظهار في رئيسية قالب الأقسام أولاً».
3. الترتيب الافتراضي للهيدر: Body Care ثم Skin Care ثم Fragrance. ترتيب الرئيسية: Fragrance ثم Body Care ثم Skin Care. لكل منهما ترتيب مستقل.
4. في العربية يجب أن تظهر أسماء الأقسام العربية فقط، وفي English يجب أن تظهر الأسماء الإنجليزية فقط. جرّب سطح المكتب وقائمة الموبايل.
5. افتح قسم العطور، ثم Women أو Men؛ يجب أن يظهر شريط الأبناء الخاص بالفرع، ثم اختر 90 ml أو 240 ml. جرّب تغيير الفرع والعودة إلى «الكل»؛ يجب ألا تبقى نتيجة مقاس الفرع السابق.
6. إذا كانت بيانات الاختبار القديمة تستخدم أقسام مقاسات مباشرة دون تحديد Women/Men، فستظل المنتجات مرتبطة بأقسامها القديمة. انقل المنتج إلى الفرع الصحيح يدوياً من نموذج المنتج بعد مراجعة نوعه؛ التهيئة لا تخمّن جنس المنتج ولا تنقل المخزون أو تحذف أقساماً.
7. بدّل إلى `classic` للتحقق من بقاء تصميم القائمة المنسدلة والدوائر القديم، ثم أعد `category_first` إذا كان هو المطلوب للمعاينة.

## النشر وتهيئة بيئة الاختبار

مسار GitHub Actions لفرع `test` يتحقق أولاً من مجلد نسخة الاختبار، ثم يحدّث الاعتماديات ويشغّل:

```bash
php artisan config:clear
php artisan migrate --force
php artisan storefront:prepare --activate-category-first
php artisan route:clear
php artisan view:clear
php artisan responsecache:clear
php artisan config:cache
```

أمر `storefront:prepare` يعمل تهيئة أولية مرة واحدة ويعيد استخدام قسم العطور القديم إذا كان رئيسياً باسم/slug معروف مثل `Body_mist`. لا يغير معرّفات المنتجات ولا إسنادها للأقسام. النشر التالي يحافظ على اختيارات المدير للقالب والظهور والترتيب.

إذا كان `TEST_DEPLOY_PATH` غير صحيح، يبحث النشر بشكل محدود تحت مجلد `domains` في الحساب عن نسخة Git واحدة تخص Violet وموقع `test.flowerviolet.com`. عند عدم وجود نتيجة وحيدة يتوقف قبل أي تعديل ويطلب تصحيح secret المسار؛ لا ينشر على نسخة الإنتاج ولا ينشئ نسخة عشوائية.

يمكن إعادة أمر التهيئة يدوياً دون تغيير اختيارات المدير بعد التهيئة الأولى:

```bash
php artisan storefront:prepare
```

يعرض الأمر الأقسام الرئيسية المختارة وأعداد الأسماء التي تحتاج ترجمة لتسهيل مراجعة البيانات.
